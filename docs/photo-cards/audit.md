# Photo-card audit — main at merged PR #35

Base: `4ec1514` (merge PR #35). Feature branch: `feat/personalised-photo-cards`.

- **Standard rendering:** `engine/card-template.html`, `engine/card-renderer.js`, `engine/card-base.css` and theme styles. Validated content populates the existing text panel, signature, art, watermark and optional gift. `checkFit()` waits for fonts, measures containment and preserves a minimum 14px message size or exposes the full text fallback.
- **Folded rendering:** `engine/physical-card.js` owns one `.paper-book` with `.paper-cover`, `.paper-left` and `.paper-right`. Envelope extraction, opening, closing, replay, focus and reduced motion are handled here. The real front face and left page are stable DOM nodes. This feature mounts local photographs inside those existing nodes and the native reverse cover face (which overlays the stationary left page when unfolded); it does not replace the controller or clone a floating cover.
- **Artwork:** `engine/illustrations.js` resolves trusted library IDs. Existing physical cover, inside-left and inside-cover artwork remains under `physicalConfig`. Local photos override presentation only while selected; choosing the traditional type restores ordinary artwork.
- **Schemas:** v1/v2 JSON query links remain supported; v3 compact/optionally deflated fragments contain text, palette and trusted art IDs; v4 adds opening configuration; v5 adds the folded document. `engine/card-data.js`, `physical-schema.js` and `share-codec.js` are unchanged. These schemas have no media reference or photo transport. The future v6 proposal is documentation only.
- **Preview:** `engine/preview.js` builds a same-origin iframe and coalesces `setCardData` calls. The sender-only `app/photo-card.js` adapter runs after normal preview updates, retaining the existing book and opening handlers. The local image CSS is injected only into `cardPreview`; it is never loaded by `viewerFrame`.
- **Sharing:** compact links are bounded to 12,000 characters and decoded data to 64 KiB. Inline photos are not a practical or private transport. All active photo modes, including missing photos, are rejected before share preparation and again after its asynchronous work. Every existing transport goes through that gate. Traditional sharing remains unchanged.
- **Drafts:** `app/drafts.js` retains the existing illustrated `silent-hello-draft-v1` localStorage record. Photo drafts use a separate IndexedDB Blob plus validated card snapshot and crop settings. No raster, base64 image or blob URL enters localStorage or card links. Restoring an illustrated draft explicitly leaves local photo mode.
- **Previous media restrictions:** the editor and tests previously prohibited all file inputs. The sender now has one raster-only input. Recipient upload restrictions are unchanged. The existing data-test HTML ban also flagged PR #35's constant occasion-dialog template; the test now explicitly audits that one constant template for absence of interpolation and retains the ban on other dynamic HTML assignments. No reminder runtime code was changed.

## Compatibility boundary

Protected recipient files, the folded renderer, opening controller, shared preview, sharing codec and card schemas are unchanged. The only integration with existing editor logic is sender initialization, an explicit photo-sharing gate and photo-aware Save/Delete draft handling. The storefront changes only its previously outdated FAQ text, and the privacy information explains local photo processing. No infrastructure, DNS, payment or AI feature is introduced.
