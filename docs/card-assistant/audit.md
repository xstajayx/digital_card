# Personal assistant audit and compatibility

Base: `a0653d8`, latest main at the start of this feature, includes merged PR #35 (My Occasions) and PR #36 (local photo cards). Feature branch: `feat/personal-card-assistant`.

My Occasions stores bounded v1 records under `silent-hello.occasions.v1`: stable ID, nickname, birthday/anniversary, month/day, annual flag, a one-time **scheduled year**, reminder interval and revision. A scheduled year is not a birth/anniversary start year. Calendar generation already handles all-day dates, leap-day recurrence, alarms, UTF-8 escaping/folding and CRLF. These calendar semantics and UIDs are preserved.

The assistant uses a validated optional profile and authoritative v2 document (`silent-hello.occasions.v2`) only when extended data is first saved. Existing v1 data is read as-is with preparation off and no inferred start year. It is not bulk-rewritten on page load. The first successful v2 write contains the complete list and leaves v1 as a recovery copy; a failed write leaves v1 usable. Once v2 exists it is authoritative, including an empty list; corrupt v2 is reported without falling back to old records and resurrecting deletions. Legacy edit paths retain existing profiles. Explicit deletion also removes the person's legacy recovery entry and associated prepared cards; a storage failure is disclosed.

Existing themes supply actual birthday, milestone, child and anniversary designs. There is no generated artwork or AI dependency. Birthday milestone themes support the old age field (1–120); larger known ages remain in the message/physical cover without extending the old codec. Anniversary years use the message/physical cover with the existing anniversary design. Unsupported preferred designs fall back to a compatible existing theme, never a nonexistent ID.

The renderer, physical book/opening controllers, illustration library, v1–v5 schemas/codecs and simplified recipient page are unchanged. The assistant's draft fit check uses the actual existing renderer at 288×480 and 680×714, and previews also check their current size. Cards that do not fit remain drafts with every word preserved. The existing editor loads a lightweight local prepared configuration and saves edits back explicitly; changed content clears approval. Prepared links require approval even through that editor, while ordinary creation/sharing remains unchanged.

PR #36 is already merged. Its local photo editor, processed IndexedDB drafts and photo-sharing prohibition remain intact. Automated preparation always uses illustrated templates and never copies photo assets annually. A sender may save a separate local photo draft while editing, but it cannot be silently stored or shared as an approved assistant card. Future persistent photos require the owned-media/token service described in `docs/photo-cards/media-architecture.md` before assistant scheduling can reference them.
